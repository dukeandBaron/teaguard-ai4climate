# 茶候自己的思考：自然系统、关系图与Transformer

本文的方法与数据判断继承自V0.2。V0.3的软件结构、故障修复和实际验收见`docs/ARCHITECTURE.md`、`docs/ENGINEERING_REVIEW.md`与`artifacts/ENGINEERING_ACCEPTANCE.json`。本轮重构没有新增训练或改变原冻结数值结果。

## 结论

工程路线`PROCEED`：本机情境—证据—任务关系图已实现，统一输入、五卡条件匹配、十例回放和网页已连接。学术首创判断为`INSUFFICIENT_EVIDENCE`；没有独立田间标签、外部效用或新模型效果，不能称论文级新算法或世界首创。

## 1. 自然可以类比成什么

对当前问题，合适的类比是“多层、部分可观测、带记忆和时延的动力系统”。天气提供外部驱动；土壤和根区储水存在记忆；地形、冠层、品种和阶段改变局部条件；管理动作又影响后续状态。

概念上可以写为：

`x(t+1) = F(x(t), 区域天气(t), 管理动作(t); 地块条件)`

`第m类观测(t) = H_m(x(t); 空间范围、时间、方法) + 误差`

这里的F/H是问题表达，当前没有拟合或校准这些物理/生理函数。一个区域气温和ET₀减降雨不足以唯一识别根区含水量、叶温或损伤。最合理的系统行为往往是保存未知、提出下一条核查，而不是猜出隐藏状态。

## 2. 哪一部分已经是网络

当前是带类型的信息关系图：

`区域天气 → 模拟地块情境 ← 土壤/遮阴/阶段反馈`

`文献与条件匹配 → 核查任务 → 模拟反馈版本`

节点表示资料或核查对象，边表示“区域参照”“情境条件”“核查依据”“待对齐差异”。它保留证据范围与来源；没有把节点假装成神经元，也没有给边随意设置生理因果权重。图不是叶片温度场，连线也不意味着测得因果效应。

本版自己的工程增量是：文献结论先通过物种/品种/环境/处理/终点的适用性检查，再参与任务解释；尺度或条件冲突被保留并转成核查项。代码在`teaguard/nature.py`，网页可点开和拖动实际节点。

## 3. 哪些位置可以用Transformer

| 位置 | 可能输入与作用 | 当前缺口与对照 |
|---|---|---|
| 天气时间编码 | 过去T天×N网格×6变量；PatchTST式分段或小型时序编码器预测固定三日天气目标 | 先与季节均值、延续、岭回归、原始业务预报及简单订正比较；按时间前滚划分，不能随机打散重叠窗口 |
| 带静态条件的预测 | TFT区分地形/地点等静态变量、历史观测、当时已知的未来预报 | 不可把实际未来天气作为“已知未来输入”；需要模型版本、起报、公开时间与同一目标合同 |
| 证据—情境交互 | 情境作query，原文/证据卡作key/value；用适用性和时间掩码过滤不合格来源 | 当前精确匹配规则是基线；若没有独立相关性/任务标签，训练注意力只会学回已有规则，不能证明收益 |
| 邻域图交互 | 图注意力或图Transformer编码相邻网格、距离、海拔等关系 | 邻域相关性极高，先检查简单邻域统计是否有增量；不能由更细表示宣称地块精度 |

本轮未新增或加载Transformer、GNN或大模型权重。V1数值基线仍是原岭回归；当前新增的是情境与证据决策层。

参考原文：[TFT](https://arxiv.org/abs/1912.09363)、[PatchTST](https://arxiv.org/abs/2211.14730)、[PatchTST作者代码](https://github.com/yuqinie98/PatchTST)。两篇论文提供架构设计，不直接证明其在本项目优于简单模型。

## 4. 适合继续形成自己的贡献的三个候选

**条件适用性先于回答的关系图。** 可检验问题：只凭检索相关性，是否会把受控基因表达、跨物种处理或区域再分析用于不支持的现场结论？本版用显式条件与支持/不支持范围约束任务解释。N06/N07检查了这些边界，软件通过不等于农业效果确认。

**固定天气的情境不变性检查。** 同一份天气下改变土壤、遮阴和阶段，数值必须不动，只有有明确规则和依据的任务可改变。本轮先执行V1原控制器并固定保存预测，确认V1对遮阴和阶段输入不产生变化；这是新增任务合同下的工程缺口，不能写成天气预测模型失效。随后用最小规则扩展运行N04/N05成对对照。

**把缺失信息转成有理由的下一问。** 本版枚举一个未知条件的有限取值，比较核查任务集合差异，显示哪条信息会改变任务。它是明确规则的分支敏感性，不是熵、贝叶斯信息价值或已求得的最优问题；观察时间/方法等来源缺口仍应优先核对。后续可比较固定顺序、规则分歧优先和随机询问，在独立来源支持的任务清单上核对遗漏和问题数量。

这三项可以作为本项目的工程贡献与可证伪研究假设。图、条件匹配、情境对照和农业决策支持均有成熟前作；本轮有界查阅也发现农业数字孪生研究已大量使用语义层和知识图谱，不能以“加图/加Transformer”宣布首创。[相关系统综述](https://doi.org/10.1016/j.atech.2026.102283)

## 5. 数据是不是少

时间记录对一个小型数值基线并不算极少：中心11年4018天；本轮新增到9网格、36162条网格—日期记录。真正短缺的是独立地区/来源、实时预报发布时间证据，以及地块根区水分、品种阶段、损伤、品质或产量标签。九个网格仍属于同一ERA5体系，原始日最高温与中心相关系数约0.997—0.999。

不能把13个AI情境输入变体当真实农业样本，也不能把36162个相关网格—日期当36162次独立田间试验。本版保留数据角色：公开区域参照、原冻结预测、AI地块情境、文献机制、待补现实证据。

下一阶段最小数值比较仍是取得合法同起报档案和可用时间证据后，比较原始业务预报与训练期简单残差订正。农业生理模型则应等到相应地块标签后再决定；当前没有从稀缺标签中制造模型效果。

## 6. 本轮能说与不能说

能说：统一输入、五卡条件检查、关系图、三档组件、十例回放与本机网页已连接；来源、未知项与版本可追溯；新增区域数据已独立核对。

尚未证明：学习到新的生理机制、比专业预报更准、真实茶园增产/节水、真实用户更快或更少遗漏、独立学术新颖性、生产部署或正式参赛成功。当前目标是把可验证的工程改进做实，再决定值得付出实验成本的最小问题。
