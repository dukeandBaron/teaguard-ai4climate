# 本机运行与维护

V0.3.1源码分发包可运行`python -B scripts/verify_portable.py`，它不要求开发者的历史绝对路径，另行输出可移植的离线检查回执。严格本机验收仍保留对V1/V2历史根目录的核对；二者不混为相同验证范围。

## 启动

在当前V3目录双击`start_teaguard_nature.cmd`，或运行：

```powershell
python -B scripts/launch_local.py
```

访问 http://127.0.0.1:50115/ 。旧V2在50114，两个目录与记录各自独立。启动器检测到同版本服务时复用；不会结束其它进程。前端使用浏览器原生ES模块，通过本机HTTP打开，不能直接双击HTML作为运行方式。

运行服务仅需已安装的Python 3.12标准库；没有新增安装。自动测试另外使用本机已有jsonschema、ruff和Node；PDF审查稿使用已有PyMuPDF。原保存预测不会触发拟合或GPU使用。浏览器运行不访问CDN或模型API。

## 检查

```powershell
python -B scripts/doctor_local.py
python -B scripts/verify_engineering.py
```

doctor为只读检查：服务版本、冻结输入摘要与数据库quick_check；不会启动服务、修库、安装依赖或调整系统设置。整体验收需要先运行服务并完成浏览器验收，使用现有浏览器回执比较当前源码。

## 记录与恢复

当前记录保存在`runtime/records.sqlite3`，最近20条摘要出现在网页，完整记录可下载JSON和Markdown。所有反馈均为模拟完成。独立分析清除前序关联，相同输入的根记录可复用，不伪造新的巡查事件。

如提示前序缺失或引擎不兼容，先查看/导出旧记录，再点击“独立分析”；程序不擅自丢弃历史。若提示内容校验失败，保留数据库与错误请求编号，停止使用该记录，不自动修复、覆盖或删除数据库。

需备份时，可先从网页下载重要记录。要备份整个数据库，在这个版本服务的控制台按Ctrl+C，确认该服务停止后复制`runtime/records.sqlite3`到明确的备份目录；保留源文件。源码ZIP故意不包含当前数据库和请求日志，不能当作运行数据备份。V2原目录与记录完整保留，本轮未自动迁移或改写历史JSON。

`runtime/requests.jsonl`只记录请求编号、路径、方法、状态与耗时，不记录请求体和地块内容；当前尚无自动轮换或无限期服务容量保证。测试临时文件只在`artifacts/engineering/`与原测试专用目录中生成并按测试清理；不清理用户项目数据。
